# FGX Memory Map

Where everything lives in a running FGX system, with the EQU that names it.
The headers are the source of truth; this page tells you which header and what
the value is today.

| What | Source of truth |
|---|---|
| Kernel/rest-of-OS bank counts, rest-of-OS offsets, kernel-bank layout, bank-0 names | `include/kernel.s` |
| Bank-0 geometry (slots, arena, DPs, BLK_STAGE) | `include/config.s`, generated by `tools/ninja/genconfig.py` from `cfg/system.cfg`; checked by `tools/check_bank0_geometry.py` |
| Kernel statics, page-3 cells, console buffers | `include/memmap.s` (DUM blocks with `ERR` guards) |
| User pool bounds | `include/loader.s` `BANK_USER_*` |
| User pool allocator | `src/kernel/bank.s` |
| Far / tty bank export tables | `include/kfar.s`, `include/ktty.s` |
| What the loader claims | `src/boot/stage2.s` (`LoaderAllocKernelBank`, `LoaderAllocRestBank`) |

## Bank numbers are assembly-time ORGs

The kernel is relocated at boot. Stage 2 claims two Memory Manager handles and
loads `/fgxunix`'s segments into them:

- **The kernel handle**: `KERNEL_BANKS` (3) contiguous, bank-aligned banks:
  the core kernel bank, the far bank (core + 1) and the tty bank (core + 2).
- **The rest-of-OS handle**: `RESTOFOS_BANKS` ($3F = 63) banks for the console,
  fonts, module window, kernel heap and user pool.

The loader writes both base banks to fixed bank-0 anchors, `KFGX_ANCHOR`
(`$00:032C`, magic `$4B` at `$032D`) and `KFGX_REST_ANCHOR` (`$00:03CC`, magic
at `$03CD`), and the kernel derives everything else from them: core-kernel
statics are DBR-relative in the live bank, the far and tty banks come from
`PHK`, and rest-of-OS regions are `_restBaseBank + REST_*_OFF`. Every bank
number on this page (`$02`, `$03`, `$08`, ...) is the assembly-time ORG, i.e.
the layout when the kernel happens to land at `$02`. Only banks `$00`, `$01`
and `$E0`-`$FF` are fixed.

**RAM.** The full claim is 3 + 63 banks beyond banks `$00`/`$01`, so 4 MB is
the realistic minimum and 8 MB is comfortable. If the Memory Manager cannot
grant 63 contiguous banks, `LoaderAllocRestBank` retries one bank smaller each
time and halts below `RESTOFOS_MIN_BANKS` (`$0C` in `src/boot/stage2.s`, the
copy the loader uses). The loader records the claim in `KFGX_REST_COUNT`
(`$00:0305`) and `Bank_Init` shrinks the user pool to fit.

## Kernel handle

| Bank (ORG) | Runtime | Contents | Defined by |
|---|---|---|---|
| `$02` | core | Core kernel: vectors/globals, TCB table, code, statics, loader handoff (layout below) | `FGX_CODE`, `FGX_DATA`, `memmap.s` |
| `$08` | core + 1 | Far kernel bank, `bin/fgxfar.bin`: code `$0000`-`$EC3F`, statics from `FGX_KFAR_DATA` (`$EC40`). Console, program loader, clock, itimers, sound, kernel C (VFS seam, root mount, `/dev` nodes, fcc runtime) | `FGX_KFAR_BANK`, `include/kfar.s`, `src/kernel/far/` |
| `$09` | core + 2 | Tty kernel bank, `bin/fgxtty.bin`: code `$0000`-`$FEFF`, statics from `FGX_KTTY_DATA` (`$FF00`). The 2.11BSD tty layer, `kern_time.c`, the shared-text table, shared-library hooks | `FGX_KTTY_BANK`, `include/ktty.s`, `src/kernel/tty/` |

The far and tty ORGs (`$08`, `$09`) are conventions only; at runtime both banks
are found from `PHK`. Design records:
[far-kernel-bank](history/plans/far-kernel-bank.md),
[tty-kernel-bank](history/plans/tty-kernel-bank.md).

### Core kernel bank

Offsets within the live core bank (`include/kernel.s`, `include/memmap.s`):

| Offset | Size | Contents |
|---|---|---|
| `$0000`-`$07FF` | 2 KB | `FGX_VECTORS` / `FGX_GLOBALS` are named here but nothing in `src/` references them |
| `$0800`-`$0FFF` | 2 KB | TCB table (`FGX_TASK_TBL`): `NPROC` (32) TCBs x 64 B, ending flush at `FGX_CODE`. No pid-0 slot: `pid = slot + 1`. Layout in `include/kernel.s` |
| `$1000`-`$EF4F` | ~57 KB | Kernel code (`FGX_CODE`) |
| `$EF50`-`$FDFF` | ~3.7 KB | Kernel statics (`FGX_DATA`; `memmap.s` `DUM FGX_DATA`), including the user-pool coremap. `ERR KMem_KGlobals_end-1/$02FE00` keeps them below `$FE00` |
| `$FF00`-`$FF17` | 24 B | Loader handoff: BlkTramp/CoutTramp entries and `_PreStaged_Banks` (`memmap.s` `DUM $02FF00`) |

Most kernel tables are not statics: the scheduler-state table
(`_schedTblPtr`), the signal-handler block (`_sigHndPtr`) and the kernel log
ring (`_kLogBufPtr`), among others, are `Kmalloc`'d at boot and reached through
direct-page long pointers (`include/dpmap.s`).

## Rest-of-OS handle

Offsets from `_restBaseBank` (`include/kernel.s` `REST_*_OFF`). The `$02`-build
column assumes `REST_BASE_DEFAULT` = `$03`.

| Offset | `$02` build | Contents | Defined by |
|---|---|---|---|
| +0 | `$03` | Console cell buffers: `CON_CHARBUF`, `CON_ATTRBUF`, `CON_FGBUF`, `CON_BGBUF` (100 x 80 each) and the alt-screen snapshots `CON_ALT_*` | `REST_CONSOLE_BANK_OFF`, `memmap.s` `DUM $030000` |
| +1 | `$04` | Pre-expanded console fonts: `CON_PREEXP_REG_BASE` (`$0000`), `CON_PREEXP_BOLD_BASE` (`$8000`) | `REST_FONTS_BANK_OFF` |
| +2..+4 | `$05`-`$07` | Module window: `vfs`, `ufs`, `ufsdir`, one bank each, pre-staged by stage 2 because they are the root filesystem | `REST_KMOD_FIRST_OFF` |
| +5..+6 | `$08`-`$09` | Kernel heap boot arenas (`KMEM_BOOT_ARENAS` = 2) | `REST_HEAP_FIRST_OFF`, `_kHeapFirstBank` |
| +7.. | `$0A`-`$41` | User pool, up to `BANK_USER_COUNT` (56) banks | `REST_USER_FIRST_OFF`, `BANK_USER_FIRST`/`BANK_USER_LAST` |

## User pool: the coremap

The user pool is a 2.11BSD resource map, `_coremap` (`src/kernel/bank.s`),
ported from `vendor/2.11BSD/usr/sys/sys/subr_rmap.c`:

- An array of `{size, addr}` pieces in address order, terminated by size 0;
  first-fit allocation and coalescing on free, as BSD's `malloc()` /
  `mfree()`. A free that needs a slot the map does not have is logged
  (`coremap: overflow, lost N pages`) as BSD's is.
- `NMAP` = `NPROC` slots of 4 bytes (`_coremap DS 128` in `memmap.s`; the
  `ERR` in `bank.s` ties the two).
- **Divergences.** The unit is a 256-byte page, not a 64-byte click, and an
  address is `bank << 8 | page`. No allocation crosses a bank, since a 65816
  segment cannot; a sub-bank request first looks for room that does not start
  a wholly free bank, so whole banks stay whole.
- `Bank_Alloc` takes a whole free bank, `Core_Alloc` a page run; `Core_Free`
  and `Bank_Free` give them back. When the pool is dry both allocators first reclaim an
  unused cached text, then an unused resident library (BSD's `xuncore()`
  retry); after that `Bank_Alloc` falls back to a Memory Manager grant
  (`_MM_ClaimBanksToRow`, a kind-3 block-table row), which never enters the map.
- `tools/coremap_model.py` models the allocator; the coremap probe checks a
  dumped map against it.

## Process memory

| Piece | Where it comes from |
|---|---|
| Code segments | The FGX2 loader (`src/kernel/far/loader.s`) gives a placeable code segment of a cacheable program a page run from the coremap (`Core_Alloc`), sharing a bank with other texts; every other segment gets a whole bank (`Bank_Alloc`). Cached code belongs to a shared-text entry (`src/kernel/tty/text.s`, 2.11BSD's `struct text` / `vm_text.c` without swap), loaded once and shared by every process running it; an unused text stays cached until the pool runs dry |
| Data bank | The break heap is the data bank's tail: `sbrk(2)` (`SYS_BRK`, `_Sys_Brk` in `src/kernel/process.s`) moves a cursor kept at data-bank `$FFFE` within `[end, $FFFE)`. Fork's snapshot copies the whole 64 KB data bank |
| Large `malloc` | `malloc()` (`toolchain/lib/libc_c/malloc.c`) sends requests `>= $F000` to `SYS_MALLOC32` (`_Kmalloc_Big`): a dedicated bank-aligned MM block at `bank:0000`, a kind-4 block-table row stamped with the owner's pid, which fork also copies. `free()` tells the two apart by offset 0 |
| Shared libraries | `ld.mod` (`src/modules/ld/ld.s`) keeps resident libraries' banks in a row table, held by no task; an unused row's banks are reclaimed when the pool is dry |
| User stack and DP | Bank 0, below |

Loadable modules other than the three pre-staged ones are placed by
`Mod_Load` (`src/kernel/modload.s`) in banks from `Bank_Alloc`: small modules
share one bank at build-time offsets (`tools/gen_modplace.py`), and `vfs`,
`ufs`, `ufsprobe`, `ufsdir`, `prodos` and `prodosw` each have a bank of their
own (`OWN_BANK`, `MOD_BANK_MAX` = 7). See [modules.md](modules.md).

## Kernel heap

`Kmalloc` / `Kfree` (`src/kernel/libc/alloc.s`) manage up to `KMEM_MAX_ARENAS`
(16) one-bank arenas. `KMEM_BOOT_ARENAS` (2) are the rest-of-OS heap banks;
when an allocation would fail, `_Kmem_GrowOneArena` takes a bank from
`Bank_Alloc` (or the Memory Manager) and adds it as a new arena. The kernel
heap is not part of fork's snapshot, which is why userland `malloc` does not
use it.

## Bank $00

Bank 0 holds everything the 65816 needs a 16-bit address for: direct pages
and stacks. `$C000`-`$CFFF` is I/O. FGX maps the language card's RAM
read/write for the life of the system (`_LC_MapRam` in `src/kernel/main.s`:
`$C08B` twice, LC bank 1), and the kernel-image slots live there.

| Address | Size | Contents | Name |
|---|---|---|---|
| `$0000`-`$00FF` | 256 | Zero page, left to the firmware (the kernel uses it as its boot DP only when loaded at `$02`) | `FGX_DP_KERNEL` |
| `$0100`-`$01FF` | 256 | Boot stack, and the stack for emulation-mode firmware calls (SmartPort, clock) | `FGX_STK_KERNEL` |
| `$0200`-`$02FF` | 256 | Unused | `FGX_SYSVARS` |
| `$0300`-`$03CD` | 206 | Fixed cells and trampolines, table below | `memmap.s` `DUM $000300` / `$000320` |
| `$03CE`-`$07FF` | ~1 KB | No layout tenant (`$0400`-`$07FF` is text page 1, never displayed) | |
| `$0800`-`$08FF` | 256 | Boot block load area, before the kernel runs | `FGX_BOOTAREA` |
| `$0900`-`$09FF` | 256 | The kernel's own direct page: the loader's handoff page, and the template every slot page is copied from | `FGX_DP_KKERN` |
| `$0A00`-`$0BFF` | 512 | No layout tenant | |
| `$0C00`-`$17FF` | 3 KB | Stage-2 boot-time buffers (`DIR_BUF` .. `K_PATH_BUF` in `src/boot/stage2.s`); not part of the derived layout | |
| `$1800`-`$19FF` | 512 | Block staging: every SmartPort transfer lands here, then is moved to the caller | `BLK_STAGE` |
| `$1A00`-`$BEFF` | 41 KB | User-stack arena, 165 pages | `FGX_STK_ARENA`, `FGX_STK_ARENA_PAGES` |
| `$BF00`-`$BFFF` | 256 | Kernel-C direct page (fcc's register file for syscall-time kernel C) | `FGX_DP_KERNELC` |
| `$C000`-`$CFFF` | 4 KB | I/O | |
| `$D000`-`$D6FF` | 1.75 KB | Kernel-image slot direct pages, 7 x 256 (LC bank 1) | `FGX_KSLOT_DP` |
| `$DE00`-`$DFFF` | 512 | Scheduler stack (`swtch` runs on it) | `FGX_STK_SWITCH` |
| `$E000`-`$FBFF` | 7 KB | Kernel-image slot stacks, 7 x 1 KB; slot 6 (`$F800`) is borrowed by boot | `FGX_STK_KTASKS`, `FGX_STK_BOOT` |
| `$FC00`-`$FCFF` | 256 | Interrupt-time kernel-C direct page | `FGX_DP_KERNELC_IRQ` |
| `$FD00`-`$FEFF` | 512 | Interrupt-time kernel-C stack | `FGX_STK_KIRQ` |

`genconfig.py` derives the geometry from `kernel.kslots` (7) and `kernel.kstk`
(1024). **`kernel.nproc` (32) does not touch bank 0**: it sizes kernel-bank
tables, the kernel-image homes and the coremap. `memmap.s` asserts that the
arena ends exactly at `FGX_DP_KERNELC`; `check_bank0_geometry.py` checks the
rest. The comment at the top of the generated block in `include/config.s`
still says "derived from kernel.nproc"; it is derived from the slot geometry.

### Page 3

`$0300`-`$03CF` is free of firmware use except `$03C8`-`$03CC`, which the ROM
IRQ path overwrites. Every cell is declared in `include/memmap.s`, several with
an `ERR` tying them to an EQU in `include/kernel.s` (modules include `kernel.s`
but not `memmap.s`).

| Address | Cell | Purpose |
|---|---|---|
| `$0300` | `_mlEntryJSL` | Module `mod_init` dispatch (5 B) |
| `$0305` | `KFGX_REST_COUNT` | Rest-of-OS banks the loader claimed |
| `$0306` | `KFGX_REST_HANDLE` | The rest claim's MM handle (4 B) |
| `$030A` | `KFGX_YIELD_MIRROR` | User-readable resched flag that fcc loop safepoints poll |
| `$030C`, `$030E` | `KFGX_LC_PROBE`, `KFGX_LC_STATE` | Language-card control and STATEREG park (`toolbox.s`) |
| `$0310`-`$0317` | `KFGX_TRAP_MAGIC/D/S/FLOOR` | Kernel fcc stack-overflow trap report |
| `$0318` | `KFGX_CUR_KDP` | The running task's kernel slot page |
| `$031A` | `LD_TRAMP` | JML to `ld.mod` |
| `$0320` | `IDROUTINE_TRAMP` | `JSR $FE1F` + `RTL` |
| `$0324` | `FPSIM_TRAMP` | JML to the soft-double dispatcher |
| `$0328` | `SYS_TRAMP` | Syscall entry, `JML _Sys_JslEntry` |
| `$032C`, `$032D` | `KFGX_ANCHOR`, `KFGX_ANCHOR_MAG` | Live kernel bank, magic `$4B` |
| `$032E`-`$03B3` | `MOD_JT_GATEWAY` (= `MOD_JT_BASE`) | Module jump table: 6-byte header + 32 JML slots |
| `$03B4` | `_simTramp` | SIM IRQ handler trampoline |
| `$03B8` | `_cdTrampJSL` | Chardev dispatch |
| `$03C2` | `_netTrampJSL` | Network op dispatch |
| `$03CC`, `$03CD` | `KFGX_REST_ANCHOR`, `KFGX_REST_ANCHOR_MAG` | Rest-of-OS base bank, magic `$4B` |

`$03BD`-`$03C1` and `$03C7`-`$03CB` are held empty so that `KFGX_REST_ANCHOR`
stays at `$03CC`, the address the boot loader writes.

### Per-task bank-0 state

- **User stack and user DP.** A task's stack reservation is 1..N pages of the
  arena (`Task_AllocStack` in `src/kernel/task.s`); its user direct page is the
  first page of that reservation (`TCB_DirectPage`). Nothing per pid is fixed
  in bank 0.
- **Overlapping reservations.** Bank 0 is a cache of user images. When the
  arena has no free run, a request of at least `kernel.stkover` pages
  (`TASK_STK_OVER_MIN`) may be placed over reservations of tasks that are not
  running; those tasks are parked (their live bytes copied to a home image in
  one of up to `UIMG_POOL_BANKS` swap banks) and restored to the same addresses
  when the scheduler next picks them (`Uimg_*`). This is 2.11BSD's u-area swap
  (`vendor/2.11BSD/usr/sys/sys/vm_swap.c`) to RAM rather than disk. Design:
  [bank0-residency-architecture](history/plans/2026-09-17-bank0-residency-architecture.md).
- **Kernel image.** A task inside the kernel runs on one of `kernel.kslots`
  (7) slots: a 1 KB stack at `FGX_STK_KTASKS + s*1024` and a direct page at
  `FGX_KSLOT_DP + s*256`, a copy of the template page with the task's identity
  stamped in. The scheduler binds a slot when it picks the task
  (`_Slot_Ensure`) and the task keeps it while it sleeps; when every slot is
  held, a sleeper's page and live stack are parked in its home image
  (`FGX_KHOME_STRIDE` = 2 KB per pid, all in one `Bank_Alloc` bank,
  `_kHomeBank`). The dispatcher checks the running slot's canary at every
  syscall entry.

## Bank $01 and the display

Bank `$01` is used only as the super hi-res shadow; no kernel code or data
lives there. The console (far bank, `src/kernel/far/console/`) draws into bank
`$01` and the hardware copies those writes to bank `$E1`, which is what the
video scans:

| Bank `$01` | Mirrors | Contents |
|---|---|---|
| `$2000`-`$9CFF` | `$E1:2000` | Pixels, 200 lines x 160 bytes (640 mode, 2 bits/pixel); `CON_SHR_BASE` = `$012000` (`include/console.s`) |
| `$9D00`-`$9DC7` | `$E1:9D00` (`SHR_SCB`) | Scanline control bytes |
| `$9E00`-`$9FFF` | `$E1:9E00` (`SHR_PALETTES`) | 16 palettes x 32 bytes |

SCB format: bit 7 = 640 mode, bit 6 = fill, bit 5 = scanline interrupt, bits
3-0 = palette. A Second Sight card, when present, is driven separately by the
`sscon` module (`src/modules/sscon`).

## Hardware configuration

Set at boot in `src/kernel/main.s`:

| Register | Address | What FGX does | Where |
|---|---|---|---|
| STATEREG | `$C068` | Clears RAMRD/RAMWRT (`AND #$CF`). Nothing sets ALTZP: the language-card RAM FGX maps is bank 0's | `_ConfigureHardware` |
| CYAREG | `$C036` | Sets fast mode (bit 7), clears shadow-all-banks (bit 4) | `_ConfigureHardware` |
| SHADOW | `$C035` | Read-modify-write. Clears bit 3 (keep super hi-res shadowing), then ORs `SHADOW_INHIBIT` = `$07` to stop shadowing text page 1 and both hi-res pages, which FGX never displays and which would otherwise stretch every store into them (hi-res 1 and 2 fall inside the user-stack arena). Bit 6 (I/O + language card) stays clear. Other bits keep their reset value | `_ConfigureHardware`, `_Shadow_InhibitUnused` |
| NEWVIDEO | `$C029` | Writes `$81` (bit 7 = super hi-res on) | `_ConfigureHardware` |

`include/hardware.s` also defines `FGX_SHADOW` = `$77`; nothing references
it.

## Protection

The 65816 has no MMU, so nothing stops a task from writing another task's
memory or the kernel's. What exists: the kernel copies user arguments through
the caller's bank, the kernel-image slot stacks and the scheduler stack carry
canaries checked at syscall entry and at every switch, and fcc's prologue
stack guard reads a per-task floor (`_fcc_stkfloor`, `FCC_STKFLOOR_DP` = `$B9`
in the task's direct page).
