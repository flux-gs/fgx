# FGX Code Provenance — Third-Party / Derived Sources

FGX is licensed under BSD-2-Clause (see [`LICENSE`](../LICENSE)). Some userland
utilities are **ports of 2.11BSD** code and therefore also carry the copyright
of **The Regents of the University of California** under the original BSD
license. The BSD license requires that the upstream copyright notice be
**retained** in redistributed source — so every derived file carries a
provenance header and is registered here.

This file is the authoritative registry. `tools/check_provenance.py` (run by
`ninja`) verifies that:

1. every file listed below exists and carries the required header markers
   (all rows, `src/` and `toolchain/` alike) -- the UCB set for a 2.11BSD-family
   row, and for a third-party row an SPDX id that MATCHES the one the row
   declares, and
2. no *other* file under `src/userland/` mentions BSD/UCB/Berkeley/Regents
   without being registered here (catching un-attributed ports before they
   land), and
3. every `vendor/...` path a row names as its upstream **resolves to a file
   that is actually vendored**. Checks 1 and 2 are about our side of the claim.
   Nothing opened the other side until apple/fgx#141, and one row had been
   pointing at a path that does not exist -- `spec_vnops.c` named
   `miscfs/specfs/`, where the file is vendored under `kern/` -- with the gate
   green throughout.

   **Existence, not authorship.** A resolving path says the claim points
   somewhere real, not that the named file is the ancestor of ours. apple/fgx#141
   measured several rows whose upstream shares almost no text with them; that is
   a wording question ("ported from" vs "reimplemented following") needing a
   per-row judgement, and it is tracked there rather than guessed at by the
   build.

**Scope caveat for check 2:** it scans tracked `src/userland/**` only. A
2.11BSD-derived file landing under `toolchain/` is verified by check 1 *if
registered*, but nothing catches it if it is never added here — `toolchain/`
is full of legitimate BSD *mentions* (fcc source discussing 2.11BSD, fixtures
named after BSD constructs), so a naive scan there would be all false
positives. Register toolchain ports by hand.

## Ports and reimplementations

THE TEST IS THE UPSTREAM TEXT A FILE CARRIES, NOT ITS LANGUAGE (apple/fgx#537).

- **A port** translates upstream routine by routine, or quotes upstream code
  beyond a sentence or two.  It carries the header below, the upstream Regents
  notice and a row here -- whether it is C or 65816 assembly.  So does a file
  written by reading upstream that reproduces its structure and answers closely
  (telnetd.c): that is a derived work in the licensing sense.
- **Original FGX code** implements a BSD design, names the source of the
  design, and quotes at most a short attributed passage.  It says
  `FGX-Provenance: none.  Original FGX code.` with the design's source, and has
  no row.  `src/modules/net/unp.s`, `src/kernel/tty/text.s` and
  `src/kernel/bank.s` are written this way.

A borderline file carries the notice: retaining an attribution that was not
strictly owed costs nothing, and dropping one that was is the error the BSD
licence forbids.

## Required per-file header

Every derived file begins with (comment syntax adapted to the language):

```
SPDX-License-Identifier: BSD-2-Clause
SPDX-FileCopyrightText: Copyright (c) 2026 flux and the FGX contributors
FGX-Provenance: 2.11BSD <util>(<section>)
  Ported from <util>(<section>), 2.11BSD.  Original work:
  Copyright (c) 1980, 1993 The Regents of the University of California.
  All rights reserved.
```

The lint requires three markers to be present: `SPDX-License-Identifier:
BSD-2-Clause`, `FGX-Provenance: 2.11BSD`, and `Regents of the University of
California`.

> **On the copyright years — THE VENDORED FILE WINS WHERE THERE IS ONE.** If a
> row names a `vendor/...` path and that file carries a Regents notice, the
> header reproduces THAT LINE VERBATIM, wording and punctuation included:
> `Regents` where it says `Regents` and `The Regents` where it says that,
> `1983,1986` where it has no space. `tools/check_provenance.py` enforces it,
> and the rule it enforces is *no invented notice* — every Regents line in a
> header must be one some named upstream actually carries. A file with two real
> upstreams carries two notices and passes.
>
> **The representative span is the FALLBACK, not the default, and reading it as
> the default is what apple/fgx#164 was.** The template above shows
> **1980, 1993** because most registered ports are 2.11BSD utilities named by
> `<util>(<section>)` with no vendored file to copy from — 117 of 148 rows —
> and for those the original SCCS-ID / `copyright[]` strings were not preserved
> through the port, so a per-utility-verified year is not available. The other
> 31 name a vendored original that carries its own notice, and sixteen of them
> had reproduced the span anyway: the 4.4BSD-Lite line `1989, 1993 The Regents`
> on files whose upstream says 1982, 1986 and 1989 and never 1993 at all.
>
> Where the upstream author is known (e.g. Bill Joy), the descriptive comment
> names them; the copyright holder is the Regents in all cases (UCB authors
> assigned copyright to the University).
>
> **`FGX-Provenance:` and the row's `vendor/...` path may legitimately differ**,
> and neither is wrong when they do. The tag names where the code came from in
> UPSTREAM's own layout — `4.3BSD-Reno miscfs/specfs/spec_vnops.c`, or a man
> page for a utility — while the row names where THIS repository vendored it
> (`vendor/4.3BSD-Reno/kern/spec_vnops.c`, the tree having flattened that
> directory). The row's path is the machine-checkable one, so the copyright
> check compares against it; rewriting the tag to match would make it less
> accurate about upstream, not more.

### softdouble -- the llvm-mos soft double

The W65816 llvm-mos fork's IEEE-754 double arithmetic in C over `unsigned long
long`, **Apache 2.0** (source, commit and checksum in
`vendor/65816-llvm-mos/README.md`).  It is the source of fcc's 64-bit double
runtime (apple/fgx#447): fcc compiles it, and the fpsim module
(`src/modules/fpsim`) serves it to every program beside the hand-written entry

## Adding a new port

When you port a BSD (or any third-party) utility:

1. Add the SPDX/`FGX-Provenance` header (above) to the top of the file,
   retaining the upstream copyright notice verbatim where available.
2. Add a row to the table above.
3. `ninja` runs the lint; it will fail if either step is missed.

Original FGX code (the kernel, drivers, the fcc toolchain, hand-written tools)
is solely under BSD-2-Clause and needs no provenance header.
