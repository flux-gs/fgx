# fcc-backend

fcc's back-end is a single-pass parser that emits Merlin32 text directly: parse_expr.c/parse_stmt.c/emit.c contain ~1600 ir_emitf() text-emission sites, and the "IR" (ir.h/ir.c) is a per-function record/replay buffer in which everything defaults to IR_TEXT (opaque rendered asm); only ~36 call sites record any of the 33 structured IrOps, and those cover exclusively int/char scalar locals/globals plus a few pointer-LOCAL slot idioms for DP-IMG promotion. Every structured pointer op and every IR_TEXT node is a basic-block BARRIER (ir.c:324), so the linear-scan {A,X,Y}+DP-IMG allocator optimizes only the clean scalar islands between text; the peephole (peephole.c, invoked at main.c:462) re-parses the final text buffer line-by-line. All TU-level output (globals section with every FGX2_LONG_PTR bank-reloc initializer, string pool, data segment) bypasses the IR entirely via fprintf, including mid-function fprintf(g_data_out,...) at emit.c:782. THE CORE ANSWER: bank correctness is NOT a type-system or IR property — the tword type word (tword.h) encodes base type + ptr/array/fn derivations with no address-space attribute, and the IR carries no pointer semantics — so the bank byte is chosen independently at each emission site from context (lc->kind, g_data_out, g_far_calls, expression shape). I counted: 21 clean PHK/PHB decision sites (12 emit.c, 3 parse_expr.c, 6 parse_stmt.c — matches flip/MATRIX.md), 68 total PHK|PHB text occurrences (the ledger's "~68"), 52 distinct writes of a bank byte into the single global DP slot _fcc_ptr+2, 13 forced-bank-0 LDAL/STAL emissions, 12 _fcc_ssp+2 (soft-stack bank) stagings, 1 hardcoded MVN $00,$00, and ~35 g_data_out mode branches. A pointer rvalue travels as A=16-bit offset + _fcc_ptr+2=bank in one shared DP global, so any nested evaluation clobbers the bank half — sites defensively re-stage it (emit.c:2218 comment "parse_expr may have clobbered _fcc_ptr+2"), which is the mechanism behind the chained-deref/tget/printf-fmt bank-drop bug family. Automatic storage spans three address spaces: params on the bank-0 hardware stack (n,S; far spill via _fcc_fp with STZ _fcc_fp+2), locals on a malloc'd soft-stack bank ([_fcc_ssp],Y — 5+ bytes per access vs 2 for n,S, the FGX1 jsh code-size overflow), and promoted scalars in DP; &param yields bank 0 while &local yields the soft-stack bank (emit.c:1930-1966). Calls: near JSR for same-bank and for libc/runtime — which is PUT wholesale into EVERY code segment (gen_sweep_link.py:91) — vs FGX2_FARCALL (JSL with linker offset patch + loader bank reloc) for cross-bank user functions; params sit 1 byte deeper under far calls (retn=3, main.c:48). Args push left-to-right with param[N-1] at offset 0, EXCEPT explicit-varargs/K&R-empty-paren callees whose param layout flips and whose call sites are reversed post-hoc by permuting recorded IR op-ranges (ir_reverse_call_args) with fail-closed die()s; printf-family varargs bypass the stack ABI entirely into static DBR-relative arrays libc_args/_hi/_bank. The far fn-ptr dispatch is 3-layered: FGX2_LONG_PTR storage reloc, 4-byte callee stash under the args, and a double-RTL trampoline (PHK+PEA return frame, push target bank+offset-1, RTL) because no 65816 instruction indirects through a DBR-relative 24-bit pointer. I also found a live structural-divergence bug: the expression-context call emitter copies struct-by-value args bank-aware ([_fcc_ptr],Y→[_fcc_ptr2],Y, parse_expr.c:742-767, comment explicitly says MVN's compile-time bank bytes are why) while its statement-context near-duplicate still emits MVN $00,$00 + PHK/PLB (parse_stmt.c:3400-3411) — wrong source bank for soft-stack/data structs AND forces DBR=PB afterward in multi-bank; MATRIX.md classified the flip "inert" but only the PHK was flipped, not the MVN banks. Verdict: the recurring bug class is structurally inevitable under (a) per-site bank convention with no typed carrier, (b) one global clobberable bank register, (c) dual near-duplicate expr/stmt emitters, and (d) single-bank builds where PB==DBR makes every wrong choice byte-identical (only 4 of 21 sites were guarded by any test before the c22-25 gap-closing); individual missed sites are incidental, their recurrence is not.

## [fundamental] Bank byte is a per-emission-site convention, not a type-system or IR property

The tword type word encodes only base type + derivation stack (ptr/ary/ftn) — no address space/bank. The IR has no pointer ops beyond local-slot idioms; all deref/global/call emission is opaque IR_TEXT. Consequently every emission site independently re-derives the bank from context via a 5-way dispatch (hw-stack bank 0 LDAL/STAL vs soft-stack _fcc_ssp+2 vs data bank PHB/DBR vs code bank PHK vs stored bank _fcc_ptr+2/[ptr],Y/gname+2), guarded by g_data_out/g_far_calls mode tests repeated at each site. Measured: 21 clean PHK/PHB decision sites, 52 separate bank-byte writes into _fcc_ptr+2, 13 forced-bank-0 LDAL/STAL lines, 1 MVN, ~35 g_data_out branches across the three emitter files. Each new C construct shape must re-implement the dispatch — this is WHY the mole count keeps growing; the flip sweep can only regression-guard shapes already reified as fixtures (README.md's own honest-coverage note).

BSD-shape: A BSD-shaped port assumes one flat pointer type; fcc's C pointer is one type at the source level but five bank conventions at codegen, so any new library construct (new deref shape, new initializer form) silently picks whichever convention the nearest existing site used.

## [fundamental] In-flight pointer is split across A and ONE shared global DP slot (_fcc_ptr+2)

The pointer rvalue convention is A=offset, bank in the single DP global _fcc_ptr+2 ($EA). Any nested sub-expression evaluation, libc JSR, or second pointer operand can clobber the bank half while the offset survives in A or on the stack. The codebase is littered with defensive idioms acknowledging this: emit_soft_local_store_ptr re-stages the bank 'because parse_expr may have clobbered _fcc_ptr+2 since emit_load_base' (emit.c:2220-2222); emit_deref_ptr_field commits the loaded bank only AFTER both halves are read (emit.c:1204-1211); printf needed dedicated _fcc_pf_fmtbank/_fcc_pf_outbank capture slots (emit.c:1862-1908); deref-stores must push the full 4-byte pointer before evaluating the RHS. Every fixed bank-drop bug in the ledger (chained *T=*U=q, c_tget, sprintf dest) is an instance of this single-channel design. It also makes pointer==pointer comparison need a special bank-widening path (emit_ptr_to_long_for_cmp, emit.c:3335).

## [fundamental] Single-bank invisibility: every wrong bank choice is byte-identical when PB==DBR, and dead single-bank branches are kept at every site

In FGX1/single-bank builds crt0 sets DBR=PB=own bank, so PHK vs PHB vs stored-bank are indistinguishable at runtime — the whole bug class is invisible to the entire golden corpus and only manifests in multi-bank binaries (elvis-scale). The measured flip matrix proves it: before the c22-25 gap-closing, only 4 of the 21 PHK/PHB sites reddened any construct when flipped; 12 sites are 'dead single-bank recovery paths' that must still be emitted and maintained (`else PHK` at every decision), and 5 more were active-but-unobserved coverage gaps. The design doubles every site (multi-bank arm + legacy single-bank arm) instead of retiring the single-bank convention.

## [major] Dual near-duplicate call emitters have DIVERGED: statement-context struct-by-value arg still uses bank-0 MVN $00,$00 + PHK/PLB

parse_expr.c and parse_stmt.c each contain a full argument-marshalling loop ('statement-context sibling of parse_expr.c site A'). The expression-context arm was fixed to copy a by-value struct arg bank-aware via [_fcc_ptr],Y -> [_fcc_ptr2],Y, with a comment explaining MVN's bank bytes are compile-time immediates and the source lives in the soft-stack bank. The statement-context sibling STILL emits TAX/TSC../MVN $00,$00/PHK/PLB: (a) it copies the struct from bank 0 regardless of the struct's actual bank (soft-stack local or data-bank global => garbage copy), and (b) the PHK/PLB afterwards forces DBR=PB, which in multi-bank breaks the seg0-code-reads-seg1-data invariant crt0_far explicitly preserves — and nothing restores DBR after. MATRIX.md classified this site's flip as 'inert', but the flip only toggled the PHK; the MVN source bank was never mutated and c25 exercises the expression-context arm (call inside a return-expression). This is a live latent miscompile AND the clearest evidence that duplicated emitters guarantee convention drift.

## [fundamental] Three address spaces for automatic storage, each with a different bank source and access cost

Params live on the bank-0 hardware stack (LDA n,S; >255 offsets via _fcc_fp with STZ _fcc_fp+2 hardcoding bank 0, gated by a Merlin-time DO on FRAMESIZE); locals live on a malloc'd soft-stack bank reached via LDY #off / LDA [_fcc_ssp],Y (~5 bytes + Y clobber per access vs 2 bytes for n,S — the measured cause of jsh overflowing FGX1's 64KB when flipped to soft-stack, per ledger); promoted scalars live in DP slots $C0-$DF. So &param produces a bank-0 far pointer (emit_addr_param_lower: LDA #0 -> _fcc_ptr+2) while &local produces a soft-stack-bank pointer (LDA _fcc_ssp+2), and struct/array locals need soft-bank staging at every element access while the same shapes as params take the LDAL bank-0 arm. Every aggregate/deref emitter must dispatch on lc->kind, and libc shims filling caller buffers must honor the pushed buffer bank rather than DBR (the stat() class). The hardware constraints are real (S is bank-0-only, 8-bit n,S displacement), but splitting one C storage class across three spaces multiplies every bank decision by three.

## [fundamental] The IR/optimizer pipeline cannot see or verify bank operations; ~98% of emission is the IR_TEXT escape hatch

ir_emitf call sites: 863 (emit.c) + 306 (parse_expr.c) + 431 (parse_stmt.c) ≈ 1600 raw-text sites vs 36 ir_record_op* sites over 33 structured op kinds — and the structured set is exclusively int/char scalar + pointer-LOCAL slot idioms for DP-IMG promotion. IR_TEXT and every pointer op are BB barriers (ir_is_bb_barrier), so the linear-scan allocator fences around all bank-carrying code; the final peephole re-parses rendered text lines (peephole.c) with no bank semantics. No pass can check, canonicalize, or even enumerate bank decisions — the flip sweep had to fall back to grepping the COMPILER SOURCE for PHK/PHB string literals (enumerate_sites.py) to find them, and optimizer-invariance of bank emission was established empirically, not structurally (MATRIX.md: default and FCC_NO_REGALLOC identical). TU-level emission (globals initializers with all FGX2_LONG_PTR relocs, string pool, plus mid-function fprintf(g_data_out) for &function constants) never enters the IR at all.

## [major] Split calling convention: near-JSR libc duplicated into every code bank; far-call ABI differs in frame depth and return instruction

User functions under --far-calls are reached via FGX2_FARCALL (JSL + linker offset patch + loader bank reloc) and return RTL; libc/runtime/shims stay near-JSR and are therefore PUT wholesale into EVERY code segment (fcc_runtime.s + libc.s + fcc_libc_shims.s + args.s per segment — gen_sweep_link.py:88-92, mirrored by gen_elvis_link.py). Consequences: (a) params sit at retn=3 vs 2 (main.c:48) so the same function body is offset-sensitive to how it is reached; (b) each bank pays the full libc footprint, shrinking usable code space per bank; (c) DBR-relative libc data must be split into libc_data.s in the data segment (the pf_pow10 class); (d) the indirect far call needs the double-RTL trampoline (emit_call_indirect) because JML [abs] fetches from bank 0 only, plus a 4-byte callee stash beneath the args since arg evaluation clobbers _fcc_ptr+2 (stash_fnptr_callee). This is coherent but deeply mode-forked: every call site carries an is_far decision and every pointer-to-function three representations (baked DA/^, FGX2_LONG_PTR, hidden data constant for runtime &fn).

## [major] Varargs are two separate ad-hoc ABIs, one non-reentrant

K&R/explicit-varargs functions get flipped callee param offsets plus caller-side RIGHT-TO-LEFT pushing implemented as a post-hoc permutation of recorded IR op-ranges (ir_reverse_call_args) with per-arg g_s_delta compensation and fail-closed die()s for unreachable shapes (by-value struct arg, raw n,S param bake) — a replay-buffer surgery characteristic of the single-pass front-end's source-replay bug class. Universal R-to-L was tried and REVERTED because hand-asm stubs read L-to-R (parse_stmt.c:4070-4072). Separately, printf-family varargs bypass the stack entirely into static DBR-relative arrays libc_args/libc_args_hi/libc_args_bank (one 1-byte bank slot per arg) — non-reentrant and a third pointer-passing convention to keep bank-correct.

## [minor] Pointer-return and NULL widening handled by scattered point patches

Return convention: A=16-bit value/offset, _fcc_long_hi for 4-byte scalars, pointer bank rides in _fcc_ptr+2 across the return. Because an int-constant RHS/return carries no bank, three separate normalize-to-bank-0 patches exist: emit_load_value_bank (#0 iff RHS g_expr_type is int/char, and only when g_data_out), the return-statement stale-bank normalize (parse_stmt.c:1890-1912, added after sed's `return(0)` leaked a stale bank into a NULL compare), and cast-site zeroing. Each is correct in isolation; collectively they show that 'a pointer must always carry a bank' is enforced by remembering to patch every producer of a bank-less pointer, not by construction.

## [minor] Dead-code accretion from incremental bank fixes

The soft-stack flip patched sites one-by-one, leaving unreachable duplicated arms: parse_stmt.c contains multiple `else if (lc) { STAL $000000,X }` branches that can never execute because the identical `if (lc)` soft-stack arm precedes them (e.g. 2739, 2791, 2860, 2877), and comments still claim 'local arrays live in bank 0' (2838, 2904) after the invariant changed. MATRIX.md separately enumerates 12 emitted-but-inert single-bank PHK branches. Incidental in effect, but it is measurable residue of the per-site-fix process and inflates the surface any auditor/regression must reason about.
