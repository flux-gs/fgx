# gno-precedent

GNO/ME + ORCA/C solved FGX's exact bug class on identical hardware by making the bank byte a mandatory part of every pointer VALUE and every ABI crossing, instead of an attribute recovered at each use site. ORCA/C has no near/far split: every C pointer is 4 bytes with the bank inside it (no `far` keyword exists anywhere in the GNO tree; syscall stubs push the full 24-bit address of errno via `ph4 #errno`), locals and parameters live on the hardware bank-0 stack with the D register pointed at the frame (`tsc/phd/tcd` in the sub/subroutine macros), so a pointer to any local is bank-0 by construction and dereference uses the 65816's one bank-agnostic primitive (DP-indirect). DBR is a single global invariant — the program's data bank — with exactly one annotated escape hatch (`#pragma databank 1`) required only at foreign entry points (signal handlers, fork children), because the kernel deliberately enters handlers with B=K (signal.c sets irq_B=irq_K=handler bank). Large programs are OMF load files: named code segments ≤64KB, the ORCA linker statically links only the needed libc modules ONCE per program into named segments (`segment "libc_stdio"` in every libc source), the GS/OS System Loader relocates segments to arbitrary banks at load time via relocation dictionaries, and all calls are uniformly JSL/RTL — there is no per-bank libc duplication anywhere, and optional dynamic segments load on demand through a loader-built jump table. The kernel is a user toolset (#3) JSL'd at $E10008 in the caller's context with toolbox stack-parameter convention; open/read/write/close are per-process-wrapped GS/OS calls via a patched GS/OS vector; results and errno return through caller-supplied full pointers, so the kernel never guesses a caller's bank. fork is not Unix fork: fork/fork2 spawn a function in the SHARED address space with a freshly allocated bank-0 stack+DP handle (1KB default) and copied fd table/signal state/prefixes; execve loads a fresh image under a new Memory Manager userID (InitialLoad2, or Restart to reuse a purgeable in-memory image) and frees the entire old image with one UserShutDown/DisposeAll(userID) — allocator-level ownership tagging gives crash/exit cleanup for free. On top of this GNO ran a genuinely BSD-shaped surface — 32 BSD signals with masks, SIGCHLD+wait, job control (pgrps, SIGTTIN/SIGTSTP), sgtty-ioctl tty layer with line disciplines, ptys, select(), pipes, preemptive 100ms round-robin, NPROC=32 — and successfully ported vi (STEVIE), less, make, tar, awk, sed, ftp, rlogin, gsh. Its documented costs and failures are the avoid-list: all process stacks share bank 0 (~64KB ceiling, recursion warnings), a big lock serializes GS/OS/Toolbox and forbids context switches inside those calls, no memory protection, fd 0/1/2 remapped to 1/2/3 (a self-inflicted porting landmine), environment lives in shell variables so execve env changes leak to the parent (documented race), no symlinks, LINK_MAX=1, 16-bit pid_t, struct-based 64-bit ints — and even with the safe model their libc still logged a "(data bank problems)" fix, so a test oracle remains necessary. ORCA/C itself self-hosted on the IIgs, an existence proof that fcc's north star is compatible with the uniform-4-byte-pointer model.

## [fundamental] Uniform 4-byte pointers at the language level eliminate the far-pointer bug class by construction

ORCA/C has no near/far dichotomy: every C pointer is 32 bits and carries its bank; the bank can never be 'dropped' because it is part of the value, not a separately-tracked attribute. The GNO tree (kernel, libc, dozens of ports) contains zero `far` annotations. The syscall ABI is consistent: stubs push the full 24-bit address of errno (`ph4 #errno` emits the bank via `pea ^errno`), and the kernel writes results only through caller-supplied full pointers. FGX/fcc's recurring 'lost _fcc_ptr+2 / dropped bank' class (~68 single-bank-invisible sites) is structural fallout of making bank-ness optional (FGX1 near vs FGX2_LONG_PTR far); GNO shows the same hardware supports correctness-by-default with performance recovered later by optimization, not by a second pointer flavor.

Evidence: ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/sys/trap.asm:39 (ph4 #errno in getppid stub); ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/sys/trap.mac:46-49 (ph4 immediate pushes bank word: pea +(&parm)|-16); grep for '\bfar\b' across ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/**/*.c: only an English-prose hit (regex/engine.c:523)

BSD-shape: BSD source ports compile unmodified w.r.t. pointers; the entire 'annotate far pointers per port' burden FGX carries does not exist in GNO.

## [fundamental] Locals on the hardware bank-0 stack with D=frame; the soft stack is the root enabler of FGX's caller-buffer-bank bugs

ORCA/C convention: stack and direct page are one bank-0 allocation per process (kernel NewHandle in bank 0; commonFork sets dPageAddr = handle base; execve uses the OMF stack segment or a 4KB bank-0 default). Function prologue is tsc/phd/tcd — D points at the frame, parameters/locals are DP-relative, and &local is always a bank-0 pointer. This aligns with the 65816's only bank-agnostic deref primitive (DP-indirect), so 'shim wrote to caller buffer in the wrong bank' (FGX's stat()/libc-shim class) cannot occur. The accepted cost is hard: ALL processes share bank 0's 64KB for stacks (FAQ warns recursion 'can only exist in bank zero... much smaller in practice'), defaults are 1KB (fork/#pragma stacksize) to 4KB (execve). FGX's malloc'd soft stack removed that ceiling but moved locals out of DP reach, forcing the multi-instruction far sequences where banks get dropped. A redesign must choose explicitly: bank-0 stacks with small-stack discipline (GNO-proven) vs soft stack with a compiler that makes bank loss impossible.

Evidence: ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/sys.c:540-543 (fork stack NewHandle, dPageAddr=*fstack); ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/sys.c:789-793 (execve default 4096-byte bank-0 stack when no OMF stack segment); ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/sys/trap.mac:200-208 (sub macro: tsc/phd/tcd frame convention); ~/projects/Retro/Apple/fgx/examples/gno-docs/faq/FAQ.gno.src:1800-1816 (bank-zero-only stack, 64K shared by all processes)

BSD-shape: BSD programs assume big stacks; GNO documented 'avoid recursion, malloc large locals' as the porting rule and it sufficed for vi/less/awk/ftp.

## [fundamental] One DBR invariant plus a single annotated escape hatch, instead of per-site bank juggling

Normal ORCA/C code runs with DBR = the program's global-data bank, established once at startup; the compiler assumes it everywhere. The only places the invariant breaks are foreign entry points — signal handlers, fork children, toolbox callbacks — and those are marked with `#pragma databank 1`, which makes the compiler save/restore and re-establish DBR in the prologue. The kernel is honest about it: signal delivery sets irq_B=irq_B1=irq_K (DBR := handler's code bank), and the docs say exactly which functions need the pragma. FGX instead re-derives DBR ad hoc (DBR≠PB gotchas, PHK-vs-PHB emit bugs, data-must-live-in-data-seg rules), i.e., the invariant is implicit and violated case-by-case. Copy: define the DBR contract ONCE in the ABI, teach fcc to enforce it, and give one explicit annotation (or calling-convention bit) for foreign-entry functions.

Evidence: ~/projects/Retro/Apple/fgx/examples/gno-docs/faq/FAQ.gno.src:1929-1938 (signal handlers: DBR unexpected, #pragma databank 1); ~/projects/Retro/Apple/fgx/examples/gno/usr.man/man2/fork.2:144-152 (fork child must restore data bank register; databank pragma); ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/signal.c:422-427 (irq_B=irq_B1=irq_K on handler dispatch); ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/stdlib/environ.c:13 (#pragma databank 1 at a kernel-called library entry)

## [fundamental] OMF segments + relocating System Loader is the large-program model; libc is linked once per program, never per bank

Programs >64KB are OMF load files of named static segments (each ≤ a bank); the ORCA linker pulls exactly the referenced libc modules into named segments (`segment "libc_stdio"`, `libc_stdlb`, START ... libc_sys__ in asm) inside the same load file; the loader (InitialLoad2) relocates every segment to whatever banks are free using the file's relocation dictionaries, patching inter-segment JSL targets and address constants at load time. All calls are JSL/RTL uniformly, so code neither knows nor cares which bank it or libc landed in. Dynamic segments add load-on-first-call through a loader-built jump table (with documented sharp edges: fatal error on OOM load, unload pitfalls). FGX's 'full libc copy PUT into every code bank' exists only because fcc's link/load model lacks load-time relocation with long calls as the default; GNO demonstrates the fix is a (small) relocating loader + one-copy static linking, not duplication. Restartability is a bonus of the same model: terminated images stay purgeable and Restart() re-execs them with zero disk I/O; concurrently-running instances are forced to separate copies (no shared text between live processes).

Evidence: ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/stdio/fclose.c:38 (segment "libc_stdio"); ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/sys.c:742-763 (GetUserID2 → Restart vs InitialLoad2, force fresh copy if userID in use); ~/projects/Retro/Apple/fgx/examples/gno-docs/refs.aug96/kern.html:1662 (ENOEXEC = not an OMF load file) and :437-454 region (restartability); gs-mcp doc tn_iigs page 22 (TN.IIGS #22: dynamic segments + jump table semantics); ~/projects/Retro/Apple/fgx/examples/gno/bin/vi/linkscr (multi-object single link of the vi port)

BSD-shape: Equivalent to a.out+ld.so-less static linking: one binary, one libc copy, position-fixed at load not at link. Ports need no awareness of banks.

## [major] Process model: shared address space, spawn-style fork2, exec via loader, memory ownership by userID

GNO never pretends to copy an address space. fork/vfork/fork2 create a process table entry, allocate ONLY a bank-0 stack+DP handle under a new Memory Manager userID, seed the child's registers (A=userID, entry PC=function), push endproc2 as the return address, and COPY the metadata that must diverge: fd table (with kernel refcount bumps per fd), siginfo, all 33 GS/OS prefixes; pgrp/ttyID/uid/gid are inherited. Documented invariant: parent must outlive forked children because children execute the parent's code allocations. execve allocates a new userID, loads via the System Loader, passes the command line as a 'BYTEWRKS'+cmdline string in X/Y (argv built by libc's parsearg in userland), then frees the ENTIRE old image with UserShutDown(oldUserID) or DisposeAll(oldUserID) — one call, because every allocation was ownership-tagged at the allocator. That tagging also powers auto-close of open files and cleanup on abnormal exit. FGX already chose spawn semantics; the things to copy are (a) allocator-level ownership tagging so exit/crash cleanup is total and trivial (relevant to FGX's FCB-refcount leak and FS write-state crash-safety issues), and (b) kernel-maintained per-process cwd/prefixes.

Evidence: ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/sys.c:518-655 (commonFork: stack handle, fd/siginfo/prefix copies, refcount bumps); ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/sys.c:812-825 (endproc2 ret-addr shove; ctx registers; ctx_B=startAddr>>16); ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/sys.c:911-931 (UserShutDown/DisposeAll of old image on exec); ~/projects/Retro/Apple/fgx/examples/gno-docs/refs.aug96/kern.html:1019-1034 (children share parent memory; parent must exist when children die; why Unix fork impossible sans VM)

BSD-shape: fork() ports need modification (documented in fork.2 CONFORMANCE); GNO accepted this deviation and still ported the BSD userland by mechanical fork→fork2/execve conversion.

## [major] Syscall ABI: kernel as a toolset called in caller context, stack parameters, errno by caller pointer

GNO syscalls are user toolset #3 functions dispatched via JSL $E10008 with the toolbox convention: caller pushes result space, then parameters left-to-right, then a 4-byte pointer to its errno word; kernel executes on the caller's stack (no stack switch) and returns via RTL. Because every out-parameter (errno, buffers, stat structs) arrives as a full 24-bit pointer, the kernel has no 'which bank is the caller's buffer in' problem — the class behind FGX's c_stat wrong-bank bug is unrepresentable. Costs GNO accepted: no isolation (kernel bugs scribble on the caller), errno is not cleared on success (must check return first), and the per-call version check was disabled for performance. The kernel's own globals are reached by phk/plb (kernel data assembled into its code bank) — the same rule FGX rediscovered as 'DBR-relative data must live in the data seg'.

Evidence: ~/projects/Retro/Apple/fgx/examples/gno-docs/refs.aug96/kern.html:1993 (JSL $E10008) and :2013-2290 (tool numbers fork $0B03 … fork2 $3F03); ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/sys/trap.asm:26-45 (result space push, ph4 #errno, ldx #callnum, jsl udispatch); ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/ctool.asm:24-31 (endproc2: phk/plb before touching kernel globals); ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/sys/trap.mac:252-265 (assertVersion disabled for performance)

## [major] BSD-shaped kernel surface (signals, job control, tty, select, ptys) proven sufficient for real ports on this hardware

GNO implements: 32 BSD signals with sigblock/sigsetmask/sigpause, SIGCHLD + wait, default/ignore/catch actions, syscall auto-restart flag (FL_RESTART); job control via process groups tied to ttys (SIGTTIN/SIGTSTP to background jobs, tcnewpgrp/settpgrp/tctpgrp); an in-kernel sgtty-style tty layer (TIOCGETP/SETP/SETC/FLUSH/LBIS..., line disciplines) with termios headers staged but tc*attr unimplemented at 2.0.6; ptys pre-configured in-kernel; select(); pipes; preemptive round-robin at QUANTUM=100ms with NPROC=32. Signal delivery synthesizes a call frame directly on the target's bank-0 stack (writes RTL-to-ctxtRestore + signum, redirects irq_PC/K/B to the handler) — no MMU needed. This surface carried working ports of vi(STEVIE), less, make, tar, awk, sed, sort, ftp, rlogin, rsh, gsh with libtermcap/libcurses/libedit. For FGX: the elvis runtime seam (fork/wait/signal/tty, task #28) has a complete, hardware-proven reference implementation here — including the exact frame layout trick for signal dispatch without an MMU.

Evidence: ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/signal.c:377-441 (synthetic stack frame + register redirect for handler dispatch); ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/tty.asm:1159-1188 (sgtty/BSD ioctl dispatch table); ~/projects/Retro/Apple/fgx/examples/gno/kern/gno/conf.h:6-14 (NPROC 32, QUANTUM 100ms); ~/projects/Retro/Apple/fgx/examples/gno-docs/refs.aug96/kern.html:976-989 (preemptive round-robin; no switch during GS/OS/Toolbox call); ~/projects/Retro/Apple/fgx/examples/gno/bin/vi/bugstevie.h (STEVIE vi port present)

BSD-shape: Deliberately 4.2/4.3BSD-shaped (sigblock era, sgtty ioctls) rather than POSIX termios; that vintage matched the 2.11BSD/netbsd-0.9 sources FGX also vendors.

## [major] GNO's documented failures and self-inflicted deviations — the avoid list

(1) STDIN/OUT/ERR remapped to fd 1/2/3 (POSIX 0/1/2) — their own FAQ tells porters to hunt down every hardcoded descriptor; a pure own-goal FGX must not repeat. (2) Environment is not a kernel object: it lives in shell variables; execve(envp) is a library wrapper over _execve, so a child's env setup mutates the parent (documented race in execve.2 BUGS) — make env part of the process image. (3) No symlinks and LINK_MAX=1 (ProDOS FS limits; even their header jokes about it) — plan the FS-map answer early. (4) Big lock: only one process inside GS/OS or the Toolbox, and NO context switch during those calls — I/O-bound workloads serialize; keep FGX's kernel preemption boundaries narrower. (5) Bank-0 stack exhaustion caps process count/depth. (6) 16-bit pid_t, 32-bit off_t, struct-based quad_t leaked into every port. (7) Non-compliant-app compat (auxType $DC00, TextTools replacement) consumed large engineering effort — FGX, owning all software in-tree, should refuse such shims. (8) Even with the safe pointer model, GNO's libc logged a fix for '%m and LOG_PID in vsprintf() (data bank problems)' — mixed asm/C still hits bank bugs, so FGX's test-visible multibank oracle remains necessary regardless of model chosen.

Evidence: ~/projects/Retro/Apple/fgx/examples/gno/NOTES/deviations:13-20 (fd 1/2/3, LINK_MAX 1) and :50-70 (type deviations); ~/projects/Retro/Apple/fgx/examples/gno/usr.man/man2/execve.2:154-171 (BUGS: envp modifies parent; environPush/Pop race); ~/projects/Retro/Apple/fgx/examples/gno/include/termios.h:1-3 ('Too bad we don't have symlinks for GNO'); ~/projects/Retro/Apple/fgx/examples/gno/NOTES/status.lib:599,624 (readlink/symlink 'not now'); ~/projects/Retro/Apple/fgx/examples/gno/lib/libc/ChangeLog (3/31/96 vsprintf data bank problems); ~/projects/Retro/Apple/fgx/examples/gno-docs/refs.aug96/kern.html:988 (no task switch during GS/OS/ToolBox call)

## [minor] Kernel/system introspection and per-process resource bookkeeping niceties worth copying cheaply

kvm_open/kvm_getproc/kvm_nextproc give ps(1) a stable process-table API without /proc; per-process copies of all 32 GS/OS prefixes give real per-process cwd; per-process file level plus auto-close-on-exit prevented the leaked-open-file reboots GS/OS suffered (directly analogous to FGX's leaked temp files / FCB refcount incidents); exec sets prefixes 1/9 to the executable's directory (self-locating binaries). All are small kernel features with outsized port-compat payoff.
