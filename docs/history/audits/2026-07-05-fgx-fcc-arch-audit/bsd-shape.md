# bsd-shape

FGX's user/kernel surface is 65 real syscalls (numbers 1-91 with gaps; dispatch table at src/kernel/syscall.s:391-482) reached via JSL $000328 + inline signature byte, with args in 16-bit A/X/Y, results as C-flag + A=errno, and X destroyed on every return. The single most structural fact for the far-pointer bug class: pointer arguments cross the boundary as bare 16-bit offsets and the kernel captures exactly ONE bank per call (_Sys_CallerBank = caller's DBR at the JSL, syscall.s:131-139), so multi-pointer syscalls whose pointers live in different banks (stat path+soft-stack buf) are inexpressible and every C wrapper hand-writes a DBR-swap shim — the shim layer is where the recurring bank-drop bugs (c_stat, c_tget*, caller-buf-bank rule) keep being minted. Second structural fact: fcc gives every struct member a 2-byte slot, and the kernel wire ABI was defined to MATCH that quirk (10-byte sgttyb, 12-byte tchars, 30-byte translated struct stat), so no byte-exact BSD struct exists and a future fcc layout fix breaks the kernel ABI. Third: there is no brk/sbrk — malloc IS a syscall returning {bank,offset} into kernel heap banks $07-$09 while code/data sit in a task bank and stacks in bank 0, guaranteeing heap/data/stack/code live in four different banks, which is the substrate of the far-pointer whack-a-mole. Process model is spawn-only (fork = ENOSYS stub at slot 2; posix_spawn/spawnX with POSIX file_actions, execve, wait/waitpid with correct BSD status<<8, pgids + TIOCG/SPGRP exist); GNO on the same hardware shipped fork2, so this is a choice whose cost is a hand-written process seam per port. Signals are the worst gap for the port queue: kernel delivers only SIGINT/SIGALRM, synchronously at syscall exit (CPU-bound code never receives them), with a register+RTL handler ABI no fcc function can satisfy, and the C-facing signal()/kill() are no-op stubs returning success. errno is declared in errno.h but no storage or assignment exists anywhere in libc (kernel-computed errnos are flattened to -1 and discarded); elvis defines its own dead cell. The libc also ships success-shaped booby traps: getenv returns \"vt100\" for any name starting with 'T' and NULL otherwise (the kernel stages real envp on the child stack that the runtime never reads), tgetent accepts any terminal, fgets always returns NULL, popen returns NULL. Filesystem namespace ops are missing wholesale — no mkdir/rmdir/rename/link/chmod/chown/utime/truncate/access/sync at syscall, FST-vtable, or libc layer — so editors' atomic rename-save is impossible and access() is re-implemented per-port via open() probes. No epoch time exists (time/gettimeofday absent; stat times zeroed despite the kernel holding ProDOS mod dates; headers promise otherwise). tty is sgtty-shaped (correct 2.11BSD flag values, ONLCR/ICRNL keyed on SG_CRMOD work) with exactly 7 ioctls and no TIOCGWINSZ/FIONREAD; select/poll are absent and SYS_POLLKEY's destructive read makes select emulation impossible per elvis's unix.c. Descriptors are solid for the subset (dup/dup2/pipe, BSD-valued O_* incl. kernel-honored O_EXCL) but there is no fcntl, no O_NONBLOCK, and a 16-fd table. Cross-cutting: the surface is documented in at least four hand-synced copies (loader.s EQUs, fgx_syscalls.inc, inline DFBs, generated doc table) plus two 141KB hand-synced libc.s files, and drift is already visible (implemented-but-undocumented GETUID/GETGID, errno claimed in the ABI doc, stale COP bank-push comments). For the immediate port queue: elvis task #28 is blocked by errno (missing), signal (stubbed at three layers), and popen/filter composition (all kernel primitives exist — pipe, dup2, spawn file_actions — only libc composition is missing); curses is blocked by no-TIOCGWINSZ and served by the baked termcap only.

## [fundamental] Syscall ABI carries at most ONE implicit pointer bank per call (_Sys_CallerBank = caller DBR at JSL); pointer args are bare 16-bit offsets

All syscall args travel in 16-bit A/X/Y with no bank bytes; the dispatcher captures exactly one bank — the caller's DBR at the JSL — into _Sys_CallerBank, and buffer-passing handlers (read/write/getcwd/stat/ioctl path copy) use it for every pointer. STRUCTURAL consequence: a syscall taking two pointers in different banks (stat(path, buf) where buf is a soft-stack local in the malloc'd stack bank and path is in the data bank) is INEXPRESSIBLE in the ABI, so each libc shim invents a private side-channel (c_stat stashes the buf bank in a DP cell and does the kernel->POSIX struct translation itself in userland; the 'caller buf bank not DBR' rule exists as tribal knowledge). Every new C-callable wrapper must hand-write a PHB/DBR-swap dance and read its own statics into registers before the swap (c_fread comment documents silent count=0 garbage when this is done wrong) — i.e. the API shape itself manufactures the recurring bank-drop bug class, one shim at a time. Docs also disagree on the mechanism: loader.s says SYS_IOCTL's 'arg-ptr bank pushed before COP' (a retired third convention), while the kernel actually uses _Sys_CallerBank.

Evidence: ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:131-139; ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:378; ~/projects/Retro/Apple/fgx/toolchain/lib/syscall.h:23-27; ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1706-1720 (c_stat two-bank workaround); ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:545-560 (c_fread DBR-swap hazard); ~/projects/Retro/Apple/fgx/include/loader.s:296-305 (stale COP push-bank convention); ~/projects/Retro/Apple/fgx/docs/userland-abi.md:441-482

BSD-shape: BSD syscalls pass uniformly-sized words on the user stack and the kernel copyin()s through a flat address space; any number of full-width pointers per call. A redesign should make every boundary pointer a full 24-bit value (or make process address spaces flat), not per-call implicit banks.

## [fundamental] fcc's 2-byte-per-struct-member layout is baked into the KERNEL wire ABI (sgttyb=10B, tchars=12B) — no byte-exact BSD struct can exist

fcc gives every struct member a 2-byte slot (chars included), so the historical 6-byte struct sgttyb becomes 10 bytes of all-shorts and struct tchars becomes 12 bytes; the kernel's per-tty images (include/kernel.s TTY_Sgttyb/TTY_Tchars) were then defined to MATCH the compiler quirk, and TIOCGETP/SETP copy 10 bytes. This couples kernel wire formats to a compiler-internals accident: fixing fcc's char packing later silently breaks every kernel<->user struct, and every BSD structure crossing the boundary (stat, sgttyb, tchars, statfs, sockaddr argblks) must be a bespoke FGX reshape with a hand-written translation shim (c_stat's 30-byte struct stat translation is one). The struct-stat header additionally promises epoch st_mtime while the shim writes 0 (native ProDOS ModDate/ModTime exist kernel-side but are dropped) — header/impl drift born of the per-struct translation burden.

Evidence: ~/projects/Retro/Apple/fgx/toolchain/include/sgtty.h:16-19; ~/projects/Retro/Apple/fgx/include/loader.s:394-396,405-409; ~/projects/Retro/Apple/fgx/include/kernel.s:453-496; ~/projects/Retro/Apple/fgx/toolchain/include/sys/stat.h:14-26; ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1800-1805 (times left 0, 'mtime epoch TODO'); ~/projects/Retro/Apple/fgx/include/fs.s:72-89 (native 15-byte ST_ image incl. ProDOS ModDate/ModTime)

BSD-shape: BSD headers define structs whose byte layout IS the ABI; ports assume field offsets. Any redesign needs fcc to support natural char packing (or an explicit ABI-struct annotation) before the kernel ABI is redrawn, or every vendored BSD source keeps needing forked headers.

## [fundamental] Heap is a SYSCALL into kernel banks — no sbrk/brk, so every malloc'd object is cross-bank by construction

malloc/free/realloc are kernel syscalls (62/63/91) returning {bank, offset} far pointers into kernel heap banks $07-$09, while a task's code/data/bss live in its own $0A-$1F bank and its hardware stack in bank $00 (and the fcc soft stack in yet another malloc'd bank). There is no brk/sbrk and no per-task heap contiguous with data. STRUCTURAL: the memory model GUARANTEES that heap, statics, stack, and code are in four different banks, so every pointer dereference must be bank-aware — this is the substrate of the ~68-site far-pointer whack-a-mole. syscall.s itself notes 'When per-task user heap lands (post-MVP)'. BSD code that assumes sbrk or pointer-comparable heap/data addresses cannot port without rework.

Evidence: ~/projects/Retro/Apple/fgx/include/loader.s:277-294,115-123; ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:4224; ~/projects/Retro/Apple/fgx/docs/userland-abi.md:33-57

BSD-shape: BSD: heap grows from end of data via sbrk; &static < heap ptr comparisons and custom allocators over sbrk are common in ports (old vi, ed). A redesign giving each process a contiguous multi-bank address window (or at least same-bank data+heap) removes the largest far-pointer generator.

## [major] Process model: fork is a dispatch stub; spawn-only; every BSD fork/pipe/exec idiom becomes a per-port rewrite

Dispatch slot 2 (SYS_FORK) routes to _Sys_Stub (ENOSYS); no vfork. The real primitives are SYS_POSIX_SPAWN/SPAWNX (43/44, with POSIX-shaped file_actions), SYS_EXECVE (11), wait/waitpid (7/82, BSD status<<8 encoding — correct). The pieces for popen/filter exist kernel-side (pipe 88, dup2 89, spawn file_actions) but libc composes none of them: c_popen returns NULL, elvis's rpipe()/filter() are acknowledged unbuildable as-written, and there is no c_wait/c_waitpid C shim at all (only register-ABI system()=spawn+wait). GNO — the historical IIgs Unix — shipped fork2+exec on the same hardware, so this is a design choice, not a hardware limit; the cost is a hand-written process seam in every port (elvis task #28's core).

Evidence: ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:393; ~/projects/Retro/Apple/fgx/src/kernel/process.s:378-396 (BSD status<<8); ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:520-538 (c_popen/c_pclose stubs); ~/projects/Retro/Apple/fgx/src/userland/elvis/system.c:4-12; ~/projects/Retro/Apple/fgx/examples/gno-docs/refs.aug96/kern.html (fork2)

BSD-shape: wait4/wait3 with rusage absent; no process resource accounting. A libc-level popen/pfork built once over spawn+pipe+dup2 file_actions would retire the per-port seams.

## [major] Signals: C-facing signal()/kill() are silent no-op stubs; kernel handler ABI (A=signum + RTL) is incompatible with fcc functions; delivery only at syscall exit

Three stacked failures. (a) c_signal and c_kill in the fcc libc return 0 without doing anything — a port installs handlers, sees success, and nothing ever fires. (b) The kernel delivers by synthesizing an RTL frame and jumping with signum in A; an fcc-compiled handler expects stack args and (same-bank) returns via RTS — no register-convention adapter exists (the stub comment defers it), so wiring the stub to the kernel today would crash. (c) Delivery is synchronous at syscall return only — a CPU-bound loop never receives SIGINT (signal.s says so explicitly); only SIGINT/SIGALRM have real delivery, all other signals are recorded then silently dropped; no sigvec/sigaction/sigblock/sigsetmask/sigpause/sigreturn, no handler masking, SIG_DFL==SIG_IGN in v1. The tty's tchars intr character round-trips but the line discipline does not act on it. This is the single biggest blocker for the elvis tty seam (task #28) and any interactive port.

Evidence: ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1979-1989; ~/projects/Retro/Apple/fgx/src/kernel/signal.s:1-38; ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:261-296; ~/projects/Retro/Apple/fgx/include/loader.s:407-409 (tchars inert); ~/projects/Retro/Apple/fgx/toolchain/include/signal.h:9-17 (fcc can't even declare signal()'s true type)

BSD-shape: 2.11BSD delivers asynchronously with sigcontext + sigreturn and a masked-handler model; ports assume EINTR from blocked reads and ^C delivery mid-computation. FGX has EINTR from nanosleep/accept only.

## [major] errno: header promises a libc-defined cell that does not exist anywhere; error codes are computed by the kernel then discarded by the C wrappers

toolchain/include/errno.h declares `extern int errno` and claims 'libc defines the cell and the syscall wrappers set it on failure'. No .s file in either libc copy defines or writes an errno symbol; libc.s says outright 'FGX has no errno facility yet' (perror appends no strerror); elvis carries its own `int errno;` that is never assigned (system.c:24-30 documents this). The kernel DOES return a correct 2.11BSD-numbered errno in A on every C=0 failure — the register-ABI layer preserves it, then every c_* wrapper flattens to -1 and drops it. So all BSD error-discrimination (EINTR retry loops, EEXIST-tolerant creates, ENOENT-vs-EACCES) silently reads 0. The fix is small (one data-seg cell + a store in the shims' failure paths) but it is a declared-yet-missing API, the worst kind for ports.

Evidence: ~/projects/Retro/Apple/fgx/toolchain/include/errno.h:5-12; ~/projects/Retro/Apple/fgx/toolchain/lib/libc.s:3287; ~/projects/Retro/Apple/fgx/src/userland/elvis/system.c:24-30; ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1604-1608 (errno->-1 flatten)

BSD-shape: Every BSD libc wrapper does `errno = r; return -1`. Also note FGX's errno VALUES diverge from 2.11BSD in places (ENOTSUP=45, ENOSYS=78 are 4.4BSD-ish; include/fs.s excerpt in the ABI doc shows ENFILE=23 vs BSD 23=ENFILE ok, but ESRCH=3/ECHILD=10 match).

## [major] Filesystem namespace API missing wholesale: no mkdir/rmdir/rename/link/symlink/chmod/chown/utime/truncate/access/sync/fsync at ANY layer

These are absent as syscalls (slots 8, 9, 13-17, 23-27, 29-36, 38 are _Sys_Stub), absent from the FST vtable (FOP_* has Mount/Lookup/Open/Read/Write/Create/Unlink/Ioctl/Bmap — no mkdir, no rename, no setattr), and absent from libc. access() is re-implemented per-port via an open(O_RDONLY) probe in elvis's machine layer — the exact 'per-tool copy of a standard function' the project's own toolchain-first rule forbids, forced by the API gap. Directory reading is SYS_LISTDIR (bulk snapshot into a buffer), not opendir/readdir, so every port's directory walk needs reshaping. fstat is ENOSYS despite open FCBs having all the data. Consequence: any port that creates directories, renames into place (the standard atomic-save idiom in editors!), or checks mtimes silently degrades or dies.

Evidence: ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:399-427; ~/projects/Retro/Apple/fgx/include/fst.s:93-118; ~/projects/Retro/Apple/fgx/src/userland/elvis/system.c:71-87; ~/projects/Retro/Apple/fgx/include/loader.s:158 (SYS_LISTDIR)

BSD-shape: rename(2) is the load-bearing call for safe-save in editors/mail; its absence forces unlink+rewrite (non-atomic — note the existing FS crash-corruption task #55 is exactly a torn-write pathology). mkdir(136)/rmdir(137) are trivial FOPs on ProDOS.

## [major] No epoch time facility: time()/gettimeofday absent; stat times zeroed; time_t is a typedef to nothing

sys/types.h promises 'time_t is the Unix epoch synthesized by the kernel' and sys/stat.h promises epoch st_mtime, but no syscall or libc function produces epoch time: the only time sources are SYS_UPTIME (raw IIgs ReadTimeHex bytes copied to the caller) and SYS_TICKS (60Hz counter), and the libc has only a ReadTimeHex toolbox wrapper. c_stat zeroes mtime/atime/ctime even though the kernel's native ST_ image carries ProDOS ModDate/ModTime. alarm(seconds) exists; 'nanosleep' takes 16-bit 60Hz ticks (misnamed, not a timespec). Everything comparing or recording times (make-like tools, editors' file-changed checks, mail, ls -l dates) silently sees 1970.

Evidence: ~/projects/Retro/Apple/fgx/toolchain/include/sys/types.h:3-14; ~/projects/Retro/Apple/fgx/include/loader.s:164-172,269-276,352-357; ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1802-1804; ~/projects/Retro/Apple/fgx/toolchain/lib/libc.s:3389-3406

BSD-shape: gettimeofday(116)/settimeofday(122) and stat times are assumed pervasively. One kernel routine converting the IIgs clock to epoch, exposed as SYS_TIME, closes most of this.

## [major] Booby-trapped success-returning stubs in the toolchain libc: getenv 'T'-prefix -> "vt100", tgetent always 1, fgets always NULL, popen NULL

c_getenv checks ONLY the first character of the name: anything starting with 'T' (TERM, but also TMPDIR, TAGS, TERMCAP...) returns the baked string "vt100"; everything else returns NULL — while the kernel and crt0 dutifully stage a real envp frame on the child stack that the runtime then never consults (posix_spawn passes empty envp; getenv reads none of it). c_tgetent returns 1 for any terminal name (single baked termcap entry). c_fgets unconditionally returns NULL ('v1 STUB... so while(fgets()) terminates') — any config-file or line-oriented reader silently sees instant EOF. These stubs return SUCCESS shapes, so ports pass their own sanity checks and misbehave later, which is precisely the silent-break class this audit is asked to flag. Environment as a facility is missing (no setenv/putenv/environ).

Evidence: ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1106-1131; ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1145-1150; ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1221-1239; ~/projects/Retro/Apple/fgx/include/loader.s:493-530 (envp staged on child stack)

BSD-shape: getenv walks environ; envp inheritance through exec is the BSD contract. FGX has the kernel half (execve/spawn stage envp per userland-abi.md section 4.4) and lacks the entire userland half.

## [major] ioctl surface = 7 tty requests with FGX-local 16-bit ids; no TIOCGWINSZ, no FIONREAD, no general ioctl C shim

Implemented requests: TIOCGPGRP/TIOCSPGRP (pgrp), TIOCGETP/TIOCSETP/TIOCSETN (sgttyb), TIOCGETC/TIOCSETC (tchars, stored but inert). The cmd is a 16-bit FGX-local id whose low byte 'echoes' BSD's 't' group rather than BSD's 32-bit _IOR/_IOW encodings, so vendored code passing real BSD TIOC values needs header substitution. There is no C-callable general ioctl() shim — only c_gtty/c_stty wrappers — so curses' ioctl(fd, TIOCGETP, &sb) call shape needs the FGX sgtty.h + shim additions per port. TIOCGWINSZ is absent (curses/elvis must get dimensions from the baked termcap li/co only, making runtime resize impossible); FIONREAD absent (and SYS_POLLKEY consumes the key, so a peek-based select emulation is documented as impossible in elvis's unix.c). ONLCR/ICRNL exist and are correctly keyed on SG_CRMOD in the kernel write/read paths.

Evidence: ~/projects/Retro/Apple/fgx/include/loader.s:381-412; ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:1366-1380,1094-1105,2189-2198; ~/projects/Retro/Apple/fgx/src/userland/elvis/unix.c:5-6; ~/projects/Retro/Apple/fgx/toolchain/lib/fcc_libc_shims.s:1570-1614 (c_gtty/c_stty only)

BSD-shape: Curses-family ports probe TIOCGWINSZ then fall back to termcap; providing a fixed-answer TIOCGWINSZ (80x24 or the console geometry) is cheap insurance. termios does not exist anywhere — sgtty only — which is period-correct for 2.11BSD ports but blocks anything newer.

## [minor] Descriptor layer: dup/dup2/pipe correct; no fcntl, no O_NONBLOCK, no select/poll, 16-entry fd table

dup (41), dup2 (89), pipe (88) exist with BSD semantics (dup2 closes target if open; pipe returns fd pair). O_* flag VALUES match 2.11BSD (O_APPEND $0008, O_CREAT $0200, O_TRUNC $0400, O_EXCL $0800 — kernel honors O_EXCL in Fs_Create) but O_NONBLOCK/FNDELAY is absent and there is no fcntl(2) at all (no F_DUPFD/F_GETFL/F_SETFL), no select/poll (SYS_POLLKEY is console-keyboard-only and destructive). The fd table clamps at 16 entries (AND #$0F in _Fd_Dup). open()'s third arg (mode) is accepted and ignored — 'ProDOS has no permission bits' — so creat(path, 0600) silently makes a world-default file; umask does not exist.

Evidence: ~/projects/Retro/Apple/fgx/include/fs.s:399-405; ~/projects/Retro/Apple/fgx/src/drivers/fs/fs.s:2538; ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:501-517; ~/projects/Retro/Apple/fgx/toolchain/include/fcntl.h

BSD-shape: fcntl(92)/select(93) are the two most commonly probed calls in 80s BSD sources after signal; their total absence at least fails LOUDLY (link error) rather than silently.

## [minor] Syscall numbering only loosely follows 2.11BSD despite the claim; several slots squat on different BSD calls

loader.s:86 claims 'Numbers follow 2.11BSD <sys/syscall.h> where the call exists in BSD'. True for exit/fork/read/write/open/close/unlink/execve(11=execv)/chdir/lseek/getpid/kill/dup. But stat=18 and fstat=28 use the RETIRED V7 'old stat/fstat' slots (2.11BSD stat=38, fstat=62); isatty=40 squats BSD lstat; getcwd=42 squats BSD pipe; getuid=21/getgid=22 squat mount/umount; signal=48 squats old sigsys; sockets 71-78 sit in BSD's mmap range (BSD socket=97); pipe=88 squats sethostname; dup2=89 squats getdtablesize. Nothing runs BSD binaries so this is cosmetic today, but any future renumbering to true BSD alignment is an ABI-v2 break (userland-abi.md section 9), and the misleading claim invites porting-by-number mistakes.

Evidence: ~/projects/Retro/Apple/fgx/include/loader.s:85-107; ~/projects/Retro/Apple/fgx/examples/2.11BSD/usr/include/syscall.h:10-60,97-147

BSD-shape: If a clean ABI break is on the table anyway, adopting the real 2.11BSD numbers (or abandoning the claim) removes a standing trap.

## [minor] Contract drift between the three syscall-surface sources of truth and the ABI doc

SYS_GETUID (21) and SYS_GETGID (22) are implemented in the dispatch table and return _kProcUid/_kProcGid (zero = root) — but they are absent from include/loader.s (the declared single source the ABI table is GENERATED from), absent from the userland-abi.md catalog, and absent from toolchain/lib/fgx_syscalls.inc. userland-abi.md section 3.6 asserts 'Global errno is a bank-static cell; libc syscall wrappers populate it' — false (see errno finding). loader.s's SYS_POLLKEY/SYS_IOCTL comment describes a 'bank pushed before COP' mechanism that no longer exists (dispatch is JSL SYS_TRAMP; bank comes from _Sys_CallerBank). Additionally the syscall numbers live in at least four hand-synced copies (include/loader.s, toolchain/lib/fgx_syscalls.inc, inline DFB literals in every shim, per-fixture _wrap.s EQUs) and the libc itself exists as two 141KB hand-synced files (src/userland/lib/libc.s vs toolchain/lib/libc.s, currently 5 diff lines apart). This duplication is the mechanism by which contract drift keeps re-entering.

Evidence: ~/projects/Retro/Apple/fgx/src/kernel/syscall.s:412-413,950-967; ~/projects/Retro/Apple/fgx/include/loader.s:88-108 (no 21/22); ~/projects/Retro/Apple/fgx/docs/userland-abi.md:427-431,489-495; ~/projects/Retro/Apple/fgx/toolchain/lib/fgx_syscalls.inc; diff src/userland/lib/libc.s toolchain/lib/libc.s = 5 lines

BSD-shape: BSD generates sysent, syscall.h, and libc stubs from ONE syscalls.master. FGX has a generator (tools/gen_syscall_table.py) for the doc only; extending it to emit fgx_syscalls.inc, the C header, and shim DFBs would collapse the copies.

## [minor] lseek carries only 24-bit offsets in registers while off_t is 32-bit

SYS_LSEEK packs fd and whence into A and the offset into X (lo16) + Y.lo (hi8) — 24 bits — and returns 24 bits. off_t is typedef'd long (32-bit). Harmless under ProDOS (16MB file cap, EFBIG=27 exists for the 'tree limit') but it is a register-packing ceiling baked into the ABI: the planned FAT32 driver (bank $06 reserved per the ABI doc's bank table) will hit it for files >16MB, and the C wrapper must silently truncate the high byte today.

Evidence: ~/projects/Retro/Apple/fgx/include/loader.s:99; ~/projects/Retro/Apple/fgx/toolchain/include/sys/types.h:11; ~/projects/Retro/Apple/fgx/docs/userland-abi.md:24-34 (bank $06 FAT32)

BSD-shape: 2.11BSD lseek takes a full off_t. If the arg ABI moves to a memory block or user stack (as the one-bank finding suggests anyway), this ceiling disappears for free.
