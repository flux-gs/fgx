# libc breakup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make libc an archive with member-level dead-strip, so a binary links
the libc it calls instead of all 195 functions -- retiring GitLab #25
permanently and unblocking the login-stack branch.

**Architecture:** Split `libc_c.c` into grouped member `.c` files and turn the
existing file into an umbrella of `#include "member.c"` lines, exactly as
`libcurses_c/libcurses.c` already does. `fgx_ar select` then emits a filtered
aggregate `libc.sel.c` per link with unselected members dropped, and the link
compiles that. One aggregated TU is preserved throughout.

**Tech Stack:** fcc `--pile`, `toolchain/src/ld/fgx_ar.py`,
`tools/ninja/seg3.py`, `tools/ninja/gen.py`, Merlin32.

Scope and measurements: `docs/history/plans/2026-08-05-libc-breakup-scope.md`.

## Global Constraints

- **The aggregated-TU model is non-negotiable.** `fgx_ar.cmd_select`'s own
  docstring: standalone per-member objects *"re-expose the cross-TU far-pointer
  hazard"*. Members are `#include`d into ONE translation unit; there is no
  per-member object file. `libc_c.c`'s pile rules -- near calls only, zero reloc
  rows, no `CALLEE_ENTER`, DBR stays the caller's data bank -- depend on it.
- **ASCII only** in every source file, comment, commit message and doc.
- **K&R C**, fcc, `int == 16 bits`, old-style function definitions.
- **Toolchain-first**: fix fcc/libc/the linker, never work around in a caller.
- `toolchain/lib/libc_c.s`, `libc_c_data.s` and `libc_c.srcsha` are GENERATED and
  CHECKED IN. Regenerate with `cd toolchain && make lib/libc_c.s` and commit them
  together. If the `.s` timestamp does not move, the Makefile did not see the
  edit -- stop.
- **Every check must go red without the change it guards.**
- Bugs found go to GitLab (`glab issue create`, project `apple/fgx`), not into
  ROADMAP.md.

## Task 1: Split libc_c.c into members, byte-identically

**Files:**
- Create: `toolchain/lib/libc_c/*.c` (~22 members)
- Modify: `toolchain/lib/libc_c/libc_c.c` (becomes the umbrella)

**Interfaces:**
- Consumes: nothing.
- Produces: the member set and their names, which Task 2 indexes.

**Proposed grouping** (adjust if the source disagrees -- record what you chose
and why): `string`, `mem`, `stdio_core`, `printf`, `scanf`, `malloc`,
`syscall_file`, `syscall_proc`, `signal`, `time`, `pwent`, `ttyent`, `crypt`,
`getpass`, `getopt`, `env`, `dir`, `stat`, `select`, `sgtty`, `atof`, `misc`.

Group so that a member is a plausible dead-strip unit. `printf` separate from
`stdio_core` matters (a tool using `write` should not drag the 259-line
`__lc_vpf`); `strcmp` next to `strcpy` does not.

- [ ] **Step 1: Record the baseline**

```bash
cd toolchain && make lib/libc_c.s
sha256sum lib/libc_c.s lib/libc_c_data.s | tee /tmp/libc-baseline.sha
wc -l lib/libc_c.s
```

- [ ] **Step 2: Split**

Move each function into its member file. Keep every `#include <...>` and the
file header comment in `libc_c.c`; append the member includes in an order that
preserves the ORIGINAL definition order, because static definitions and
file-scope declarations are order-sensitive in one TU.

`libc_c.c` ends as:

```c
/* ... existing header comment, unchanged ... */
#include <errno.h>
/* ... all existing system includes, unchanged ... */

#include "string.c"
#include "mem.c"
/* ... in original definition order ... */
```

- [ ] **Step 3: Prove it is byte-identical**

```bash
cd toolchain && make lib/libc_c.s
sha256sum -c /tmp/libc-baseline.sha
```

Expected: both files **OK**. This is the whole verification for this task -- a
pure refactor that changes one byte of output is a bug, and the hash says so.

If the hashes differ, do NOT proceed and do NOT adjust the baseline. Diff the
two `.s` files and find out why; the likely cause is member ordering changing a
static's position or a declaration moving after its first use.

- [ ] **Step 4: Prove the check discriminates**

Move one function into a different member so the definition order changes,
rebuild, and confirm the hash check FAILS. Restore, confirm it passes.

- [ ] **Step 5: Commit**

```bash
git add toolchain/lib/libc_c/ toolchain/lib/libc_c.s toolchain/lib/libc_c_data.s \
        toolchain/lib/libc_c.srcsha
git commit -m "refactor(libc): split libc_c.c into archive members

Pure refactor, verified byte-identical: the regenerated libc_c.s and
libc_c_data.s hash the same before and after.  libc_c.c keeps its header and
system includes and becomes an umbrella of member includes, mirroring
libcurses_c/libcurses.c.  Member order preserves the original definition
order, because one TU makes statics and file-scope declarations
order-sensitive.

No archive yet and no link site changed -- this is the split alone, so that
the next commit's behaviour change lands against a proven-inert base."
```

## Task 2: Publish libc.fgxa

**Files:**
- Create: `toolchain/lib/libc.fgxa/index.json` (generated)
- Modify: `tools/ninja/gen.py` (archive build rule)

**Interfaces:**
- Consumes: Task 1's member set.
- Produces: an archive index `fgx_ar select` can read. Tasks 4 and 5 consume it.

Read `toolchain/lib/curses.fgxa/index.json` first: the index carries `lib`,
`members` (each with `id`, `s`, `exports`, `imports`), `aggregate` (the umbrella
`.c` path) and `cc` (the compile command). Curses uses
`./fcc --pile-far-extern -DNOSCCS -Ilib/libcurses_c`; libc's `cc` must be
whatever `make lib/libc_c.s` uses today -- read the Makefile rule, do not guess.

- [ ] **Step 1: Find how curses.fgxa is built**

```bash
grep -rn "fgx_ar\|fgxa" toolchain/Makefile tools/ninja/gen.py
```

Identify the rule that runs `fgx_ar index` and mirror it for libc. If curses's
archive is built by hand rather than by a rule, say so in your report -- that
changes what Task 2 has to add.

- [ ] **Step 2: Build the index and inspect it**

```bash
cd toolchain && python3 src/ld/fgx_ar.py index --lib libc \
    --aggregate lib/libc_c/libc_c.c --outdir lib/libc.fgxa   # adjust to the real CLI
python3 -c "import json;d=json.load(open('lib/libc.fgxa/index.json'));\
print(len(d['members']),'members');\
print([m['id'] for m in d['members']])"
```

Expected: one member per file from Task 1, each with a non-empty `exports` list.
A member with NO exports is a bug -- it can never be selected, so anything in it
is unreachable.

- [ ] **Step 3: Sanity-check the symbol universe**

Assert that every function the old monolith exported is exported by exactly one
member:

```bash
cd toolchain && python3 - <<'PY'
import json, re
idx = json.load(open('lib/libc.fgxa/index.json'))
seen = {}
for m in idx['members']:
    for s in m['exports']:
        seen.setdefault(s, []).append(m['id'])
dupes = {s: v for s, v in seen.items() if len(v) > 1}
print('members:', len(idx['members']), 'symbols:', len(seen))
print('DUPLICATE EXPORTS (must be empty):', dupes)
PY
```

Expected: no duplicates. `index_members` treats a duplicate export as a fatal
ambiguity, so a duplicate here becomes a link failure later.

- [ ] **Step 4: Commit**

```bash
git add toolchain/lib/libc.fgxa tools/ninja/gen.py build.ninja
git commit -m "build(libc): publish libc.fgxa

The archive index over Task 1's members.  No link site uses it yet -- the
next tasks convert the consumers, so a bad index fails loudly here rather
than inside a 210-template sweep."
```
