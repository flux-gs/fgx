## Reframe — what Phase 0 already delivered vs. what T6 still owes

Phase 0 killed the *shim bug class* (the recurring `_Sys_CallerBank` PHB/PLB
hand-rolling) via the `SYSCALL_PTRARG` macro, and wired errno *writes*.  That
shrinks T6 to the genuinely-inexpressible cases + errno *decode*:

**Already done (Phase 0, merged):** SYSCALL_PTRARG macro; 9 broken + 5 missing
shims correct; errno cell + per-shim writes; c_stat 2nd-ptr uses the pushed
far-ptr bank (the caller-buffer-bank rule, ledger-verified).

**T6 still owes (this stage):**
1. **errno decode** — `strerror()` does not exist ("FGX has no errno facility
   yet", libc.s:3341); `perror` prints a fixed `": error\n"` suffix
   (libc_data.s:273).  This is the actual T7 port-queue unblocker (elvis #28,
   curses print meaningful errors).  The *writing* is done; only *decode* missing.
2. Kernel-side confirmation/completion that the widened calls **read the pushed
   far-ptr bank** for their 2nd+ pointers, not `_Sys_CallerBank`.
3. WAIT/WAITPID status far ptr in TCB, subsuming `TCB_DataBank`.
4. socket argblk bank fields.
5. LISTDIR + EXECVE/SPAWN pushed-args/arg-block convention.
6. wire-struct layout audit (B-8 landmine).

## Design invariants (carry forward — do not violate)

- **Hybrid, additive.** Widen only the 9–11 multi-pointer/deferred-write calls.
  **Keep `_Sys_CallerBank` for the 22 single-pointer calls** — one ptr ⇒ one
  bank ⇒ the shim DBR-swap is exact and proven.  No sentinel, no flag day; spare
  register bytes (MALLOC bank-in-A.lo precedent) + extended argblk fields, so old
  wire formats keep working per-syscall.
- **Dispatcher invariants** (`feedback_dispatcher_invariants`): DBR/REP/N-Z/
  X-clobber/CLI contracts hold across every edit.
- **libc-shim caller-buffer-bank rule** (`feedback_fcc_libc_shim_caller_buf_bank_not_dbr`,
  survives P3-3): a shim filling a caller buffer uses the caller's pushed buf
  bank, NOT DBR.  Under P3-3 a bank-0 HW-stack local ≠ DBR and a data-bank
  global ≠ shim DBR — so cross-bank STAT/waitpid are the real, now-more-likely
  failure cases (P3-3 moved locals to bank 0).
- **B-8 landmine** (`project_fgx_audit_live_defects_2026_07_05`): `sgttyb` /
  `tchars` wire structs are deliberately ALL-SHORT and MUST STAY short — a ruled
  decision, not a compiler accident.  Any change there needs **The maintainer's sign-off**.

### I1 — real errno decode: `strerror()` + `perror()` + stdio errno sweep (TOOLCHAIN libc)
- Add `strerror(int)` → static message table over the `errno.h` enumeration
  (ENOENT..ENOSYS, sparse codes).  DBR-relative string data lives in
  **libc_data.s** not libc.s (`feedback_fgx_libc_dbr_data_must_be_in_data_seg`
  — data read DBR-relative must be in the data seg, else zeros in multi-bank).
- Rewire `perror`/`c_perror` to emit `msg + ": " + strerror(errno) + "\n"`,
  replacing the fixed `": error\n"`.
- **★Fable-review gap: close the stdio-shim errno hole.**  The macro-driven
  direct-syscall shims already `STA errno` (verified), but `c_fopen`/`c_freopen`
  DISCARD the errno libc `fopen` returns — `_libc_ptrret` (shims.s:535-549) homes
  the FILE* with no `STA errno`, so `if(!(fp=fopen()))perror(name)` prints a STALE
  errno even after strerror lands — exactly the elvis/curses T7 case.  I1 must
  sweep the stdio shims that surface failure: fopen/freopen (minimum), audit the
  fclose/fseek/fputc tails.  Confirm the fopen internal failure ABI first
  (A=errno vs A=0) before adding the store.
- **Test (end-to-end, fail-closed):** a userland tool that triggers failing
  syscalls via **both** a raw `open(2)` AND a `fopen(3)` (the stdio path Fable
  flagged), printing `errno` + `strerror(errno)` + `perror`.  Validate decoded
  strings against a host C reference (`feedback_validate_against_c_reference`).
  New runtime probe → wire its verdict via `expect.check_script` in mame_test
  run.py (argv_floor is the model); RED-prove it.
- Gate: `./run.sh` goldens + stack_check + `run_runtime.py` 0 regressions;
  FGX `./build.sh disk` + the new MAME test green.

### I2 — STAT cross-bank PATH fix (SHIM-first; likely ZERO kernel edits) + FSTAT
- **★Fable-review correction: the broken pointer is the PATH, not the dst.**
  The dst POSIX `struct stat` is ALREADY handled correctly — c_stat translates
  the native image into the caller buffer via the pushed far-ptr `[_fcc_ptr]`
  (shims.s:2242-2285), so the plan's original "stat into a bank-0 local struct"
  RED test passes today.  The live corruption: c_stat sets `DBR = path bank`
  (PLB from 10,S, shims.s:2262-2264) and passes `X=#_libc_lstrBufA` as the
  SYS_STAT dst; the kernel writes the 15-byte native image via `_Sys_CallerBank`
  (= path bank) at syscall.s:2617-2637.  A path in a **bank-0 HW-stack local
  `char[]`** — the COMMON case post-P3-3 — scribbles 15 bytes at
  `$00:_libc_lstrBufA` (kernel bank-0 territory) and reads garbage back.
- **Fix = shim-only, the c_fopen model:** stage the PATH into DBR scratch via
  `_libc_lstr_to_dbr` (exactly what c_fopen does at shims.s:563-572; use a scratch
  buf distinct from the native-image `_libc_lstrBufA`, e.g. `_libc_lstrBufB`).
  Then SYS_STAT runs with DBR = libc data bank and both kernel pointers live in
  one bank → the existing single-bank `_Sys_CallerBank` contract is exact.  No
  kernel STAT widening needed for the C-shim path.
- **FSTAT is still a stub** (`syscall.s:430 DA _Sys_Stub ; 28: SYS_FSTAT`) — it
  gets born with a clean ABI when implemented; no "widening" of an existing wire.
- Kernel Y-register STAT widening only serves hand-asm callers (all single-bank
  today).  IF built: state the sentinel caveat the audit raised — `Y=$00` is a
  real bank, so "Y=0 ⇒ CallerBank" only holds because no legit dst lives in bank 0.
  Y is deliverable (dispatcher stages user Y at syscall.s:198-201).  Default: skip.
- **RED test:** `stat()` a file whose PATH is a bank-0 HW-stack local `char[]`
  (any dst); verdict = struct correctly filled, no sub-bank scribble.  check_script.

### I3 — WAIT/WAITPID status via register-return (FGX kernel) — NOT a TCB far ptr
- **★Fable-review: simpler design than the TCB far ptr.**  `_waitpid_WriteStatus`
  (process.s:1120-1138) ALWAYS writes status through `TCB_DataBank`, ignoring
  `_Sys_CallerBank` entirely — so c_waitpid's `SYSCALL_PTRARG 8` swap has never
  affected the status write.  A bank-0 `int status` local corrupts the data bank
  TODAY, on the immediate (zombie) path too, not just the deferred one.
- **Fix: return status in Y on the C=1 path; the shim stores it through its
  pushed far ptr.**  Both handler exits already run to completion in the caller's
  resumed context (`LDA _wt_childPid / SEC / RTS`, process.s:1089-1115); status
  is only 16 bits.  Y-return is an established dispatcher contract
  (`_Sys_SavedRetY`, syscall.s:230-235; LSEEK / MM_ALLOC precedent).  This DELETES
  the deferred cross-context write AND `TCB_DataBank`'s status role — no TCB growth.
- **RED test:** waitpid a child into a bank-0 HW-stack local `int status`; verdict
  = status correct, no data-bank scribble.  check_script.
- **I4/I5 exit-criterion gate (do at I3 close):** verify whether elvis #28's
  runtime seam (system/popen → SPAWN, nested `char *argv[]` 16-bit arrays that
  inherit CallerBank, loader.s:1137,1165) stages argv into data-bank scratch.  A
  bank-0 local `char *argv[]` under P3-3 is the SAME bug class as I2/I3.  If the
  system/popen shims already stage argv safely, I4/I5 defer cleanly; if not, I5
  is NOT YAGNI and must be built.  Confirm before scoping I5 out.

### I4 — socket argblk bank fields (FGX kernel + libc shims)

        can't reproduce the wire layout) — kernel-crossing but nothing to audit;
        the socket-argblk bank widen is the tracked T6/I4 remainder.  Other
        candidates are non-items: dirent = NUL-stream (no struct); DMESG/MEMINFO/
        KSTAT consumers are hand-asm (no C mirror); struct tm / timeval / FILE /
        jmp_buf / passwd = userland-only; the argv/envp loader frame is an asm
        contract (I5 turf), not a C struct.
      - **★TAP DURABILITY caveat (Fable):** abiprobe.json's `$00:0100` tap is
        the offset of abiprobe's `_libc_lstrBufA` (a libc_data.s / seg1 symbol).
        STABLE across shim RED/GREEN cycles (those edit seg0/code only), but a
        future change to libc_data.s field order BEFORE _libc_lstrBufA would move
        it and silently disarm the I2 gate (the $00:0100 snapshot stays all-zero
        either way).  If libc_data.s is reordered, re-derive from abiprobe's
        fresh seg1.lst (`grep _libc_lstrBufA`) and update the tap's `addr_hex`.
